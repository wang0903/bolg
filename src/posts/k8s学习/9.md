#  Sealos Kubernetes 集群，新加工作节点

## 1. 故障背景

### 故障现象

控制节点 `master01` 的 Sealos 配置文件丢失：

```
/root/.sealos/default/Clusterfile
```

导致：

```
sealos add --nodes x.x.x.x
```

报错：

```
Error: `master` role not found, due to Clusterfile may have been corrupted?
```

同时新增节点 join 时出现：

```
could not find a JWS signature in the cluster-info ConfigMap
```

以及：

```
tls: failed to verify certificate:
x509: certificate is valid for xxx, not 10.103.97.2
```

# 2. 恢复 Clusterfile

## 2.1 从其他 Master 节点恢复

其他正常 Master：

```
master02
192.168.1.231
```

存在：

```
/root/.sealos/default/Clusterfile
```

备份：

```
sudo tar czf /tmp/sealos-default.tar.gz \
/root/.sealos/default
```

复制到故障节点：

```
scp /tmp/sealos-default.tar.gz root@master01:/tmp/
```

恢复：

```
sudo mkdir -p /root/.sealos

sudo tar xzf /tmp/sealos-default.tar.gz \
-C /
```

验证：

```
ls /root/.sealos/default/
```

应该存在：

```
Clusterfile
etc
pki
tmp
```

# 3. 修改 VIP 配置（重点）

## 3.1 查看当前 VIP

文件：

```
/root/.sealos/default/Clusterfile
```

检查：

```
grep -n "defaultVIP" \
/root/.sealos/default/Clusterfile
```

错误：

```
defaultVIP: 10.103.97.2
```

正确：

```
defaultVIP: 192.168.1.238
```

同时：

```
vip: $defaultVIP
```

保持不变。

------

# 4. 清理旧 join 缓存

Sealos 会缓存 kubeadm join 文件。

检查：

```
grep -R "10.103.97.2" \
/root/.sealos/default/
```

如果发现：

例如：

```
tmp/192.168.1.229/kubeadm-join-node.yaml
```

不要删除，先备份：

```
mv \
/root/.sealos/default/tmp \
/root/.sealos/default/tmp.bak
```

重新创建：

```
mkdir -p /root/.sealos/default/tmp
```

------

# 5. 修复 kubeadm bootstrap 签名问题

## 5.1 检查 controller-manager

三个 master：

```
master01
master02
master03
```

检查：

```
kubectl get pod \
-n kube-system \
| grep kube-controller-manager
```

确认参数：

```
kubectl get pod \
-n kube-system \
kube-controller-manager-master01 \
-o yaml | grep controllers
```

必须包含：

```
--controllers=*,bootstrapsigner,tokencleaner
```

三个节点都需要。

# 6. 修复 bootstrap-signer RBAC

检查：

```
kubectl get clusterrole \
system:controller:bootstrap-signer
```

如果不存在：

创建：

```
kubectl apply -f - <<EOF
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRole
metadata:
  name: system:controller:bootstrap-signer
rules:
- apiGroups:
  - ""
  resources:
  - configmaps
  verbs:
  - get
  - list
  - watch
  - update

- apiGroups:
  - ""
  resources:
  - secrets
  verbs:
  - get
  - list
  - watch
EOF
```

绑定：

```
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding

metadata:
  name: system:controller:bootstrap-signer

roleRef:
  kind: ClusterRole
  name: system:controller:bootstrap-signer
  apiGroup: rbac.authorization.k8s.io

subjects:
- kind: User
  name: system:kube-controller-manager
```

验证：

```
kubectl auth can-i update configmap/cluster-info \
-n kube-public \
--as=system:kube-controller-manager
```

结果：

```
yes
```

# 7. 验证 VIP 证书

检查：

```
openssl s_client \
-connect 192.168.1.238:6443 \
-showcerts
```

证书 SAN 必须包含：

```
192.168.1.238
```

否则 join 会失败。

------

# 8. 添加 Worker 节点

Worker 不需要配置 VIP。

执行：

```
sealos add --nodes 192.168.1.229
```

生成的：

```
kubeadm-join-node.yaml
```

必须：

正确：

```
apiServerEndpoint:
  192.168.1.238:6443
```

错误：

```
apiServerEndpoint:
  10.103.97.2:6443
```

------

# 9. Worker 节点加入失败处理

如果之前加入失败：

登录 Worker：

```
ssh 192.168.1.229
```

清理：

```
sudo kubeadm reset -f

sudo rm -rf /etc/cni/net.d

sudo systemctl restart containerd
```

重新：

```
sealos add --nodes 192.168.1.229
```

# 关键修改总结

| 位置                                | 修改                                                |
| ----------------------------------- | --------------------------------------------------- |
| `/root/.sealos/default/Clusterfile` | 恢复并修改 defaultVIP                               |
| `defaultVIP`                        | 10.103.97.2 → 192.168.1.238                         |
| `tmp/kubeadm-join-node.yaml`        | 删除旧缓存重新生成                                  |
| 三个 master kube-controller-manager | 增加 `--controllers=*,bootstrapsigner,tokencleaner` |
| RBAC                                | 创建 `system:controller:bootstrap-signer`           |
| Worker 节点                         | 无需配置 VIP，只访问 VIP:6443                       |
| 加入前                              | 清理 worker kubeadm 残留                            |

------

这次事故的根因可以总结为：

**Sealos Clusterfile 丢失 + VIP 配置变化 + kubeadm bootstrap-signer 权限缺失，导致新增节点无法通过 kubeadm discovery。**
